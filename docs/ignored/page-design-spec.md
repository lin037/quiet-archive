# 页面与模块设计规范

## 文档目的

本文档不规定最终像素级编排，而是规定页面必须承担的职责、模块边界、模块能力和不允许出现的设计行为。

设计师可以自由发挥版式、节奏、动效和视觉细节，但不能突破这里定义的产品边界。

## 总体设计原则

页面整体应呈现“个人学术档案馆”的气质。

必须遵守：

- 黑白灰为主，绿色只做点睛。
- 页面以内容、结构和阅读为中心。
- 不做营销式 hero。
- 不做过度卡片化。
- 不使用大面积渐变背景。
- 不使用强烈装饰图形抢占内容注意力。
- 有图片和无图片两种状态都必须完整。
- 字体、网格、细线、编号、留白、密度承担主要识别度。
- 交互只在必要位置出现，不能让页面像社交产品。

允许自由发挥：

- 首页首屏构图。
- 模块排列顺序。
- 字体组合。
- 档案编号风格。
- 微妙动效。
- 作品展示密度。
- 目录树、时间线、章节导航的具体形式。

## 全局模块

### 顶部导航

职责：

- 提供主入口。
- 保持克制，不抢首屏。

建议入口：

- 首页。
- Archive。
- Writing。
- Columns。
- Works。
- Search。
- About。

规则：

- 不做大型菜单。
- 不做营销式 CTA。
- 不把 logo 做成唯一识别来源。
- 移动端必须保持可用，不遮挡正文。

### 搜索入口

职责：

- 快速打开搜索。
- 支持键盘优先。

必须能力：

- 输入关键词。
- 展示匹配结果。
- 显示内容类型、标题、摘要、路径。
- 支持中文搜索结果。

规则：

- 搜索 UI 可以是独立页面，也可以是浮层。
- 搜索结果不做无限信息流。
- 不需要高级筛选面板，除非基础搜索已经稳定。

### 档案元信息

职责：

- 在小角落提供内容规模和更新状态。

可展示：

- 总内容数。
- 最近更新。
- 内容类型数量。
- 当前页面路径。
- 阅读时间。
- 章节编号。

规则：

- 元信息是辅助，不做大面积数据看板。
- 第一版不展示真实浏览量。

## 页面规范

### 首页

首页是“个人档案入口”，不是营销落地页。

必须模块：

- 个人档案头部。
- 当前关注。
- 精选作品。
- 最近写作。
- 活跃专栏。
- 档案脉搏。

模块职责：

- 个人档案头部：让读者第一眼知道作者是谁、气质是什么、正在关注什么。
- 当前关注：展示近期工程、写作或研究方向。
- 精选作品：给同行和朋友快速理解作者能力的入口。
- 最近写作：证明网站是活的。
- 活跃专栏：承载长期主义和大体量内容。
- 档案脉搏：提供内容数量、最近更新等轻统计。

不允许：

- 大面积营销口号。
- “欢迎来到我的博客”式空泛首屏。
- 大头像加长介绍的普通个人主页模板。
- 用纯装饰图片撑满首屏。
- 首页所有内容都做成同质卡片。

设计自由：

- 可以使用档案编号、侧栏、表格、索引页、目录页、论文封面等隐喻。
- 可以让首屏像一张个人研究档案。
- 可以在宽屏和移动端使用不同信息密度。

### 混合归档页

职责：

- 展示所有 published 内容。
- 支持按时间、类型、目录、标签浏览。

必须模块：

- 归档标题区。
- 类型筛选。
- 内容列表。
- 时间或目录辅助导航。

规则：

- 默认应能扫描大量内容。
- 列表必须显示类型、标题、日期、摘要或路径。
- 不依赖封面图。
- 不把归档页做成作品集瀑布流。

### 类型页

职责：

- 展示某一 type 的内容集合。
- 使用该 type 的默认展示方式。

各类型默认方向：

| Type | 页面气质 |
| --- | --- |
| `article` | 正式、清晰、适合长文 |
| `note` | 时间线、片段、轻量 |
| `answer` | 问题驱动、结论清楚 |
| `project-log` | 阶段、进展、时间感 |
| `column` | 书籍、卷、章节、长期 |
| `work` | 作品档案、证据、链接 |
| `experiment` | 目的、过程、结果、备注 |

规则：

- type 页可以有各自气质，但不能像七个不同网站。
- type 的默认展示由 `posts/<type>/README.md` 决定。

### 目录页 / 专题页

来源：

- 任意目录下的 `README.md`。

职责：

- 说明该目录的主题。
- 展示子目录和内容条目。
- 作为知识组织的中间节点。

必须模块：

- 目录标题。
- 目录说明。
- 子目录列表。
- 内容列表。
- 路径或层级提示。

规则：

- 目录页不是普通文章页。
- 目录正文可以存在，但导航职责优先。
- 没有正文时也要能作为索引页成立。

### 内容详情页

职责：

- 提供稳定、舒适、可分享的阅读体验。

必须模块：

- 标题。
- 类型。
- 日期和更新时间。
- 摘要。
- 正文。
- 目录或标题导航。
- 标签。
- 分享图入口或分享提示。
- 上一篇/下一篇或同目录导航。

规则：

- 正文宽度必须适合长时间阅读。
- 代码块必须清晰可读。
- 图片不能破坏正文节奏。
- MDX 组件必须与正文视觉系统一致。
- 不做评论区。
- 不做社交点赞收藏。

### 作品页

职责：

- 展示项目、工具、系统、实验成品。
- 帮读者理解作者做过什么。

必须模块：

- 作品列表。
- 精选作品。
- 作品状态。
- 技术标签。
- 外部链接，如 GitHub、Demo、文档。

规则：

- 作品页可以比文章页更视觉化，但仍然保持档案气质。
- 图片是作品证据，不是装饰背景。
- 每个作品要有清晰的“是什么、做了什么、价值是什么”。

### 专栏页

职责：

- 承载长期、大体量、连续性内容。

必须模块：

- 专栏介绍。
- 卷或章节目录。
- 更新状态。
- 章节列表。
- 阅读入口。

规则：

- 可以容纳技术系列，也可以容纳文学、故事、世界观内容。
- 不允许因为文学内容而切换到花哨视觉风格。
- 章节导航必须清晰。

### 搜索页

职责：

- 快速找到内容。

必须模块：

- 输入框。
- 结果列表。
- 空状态。
- 加载状态。
- 结果类型标记。

规则：

- 搜索是工具，不是内容消费页。
- 输入和结果必须键盘友好。
- 中文搜索结果优先保证可用和速度。

### 关于页

职责：

- 解释作者是谁、关注什么、如何联系。

必须模块：

- 简短个人介绍。
- 技术方向。
- 当前关注。
- 代表作品入口。
- 联系方式或外部链接。

规则：

- 不写成长篇自传。
- 不写营销式履历。
- 不和首页重复过多。

### 统计页

职责：

- 第一版展示生成型档案数据，而不是真实访问数据。

可展示：

- 总内容数。
- 各 type 数量。
- 最近更新。
- 活跃专栏。
- 作品数量。
- 标签分布。

规则：

- 第一版不要求浏览量。
- 不为了统计页引入运行时数据库依赖。
- 统计页可以晚于其他核心页面实现。

## 模块设计规则

### 内容卡片

内容卡片只用于重复列表项，不用于包裹整个页面区块。

必须显示：

- 类型。
- 标题。
- 日期或更新状态。
- 摘要或路径。

可选显示：

- 标签。
- 阅读时间。
- 所属目录。
- 封面缩略图。

规则：

- 没有封面时不能显得残缺。
- 不做大圆角卡片堆叠。
- 同一页面内卡片密度要一致。

### 标签

职责：

- 提供横向关联。

规则：

- 标签是辅助信息，不是主导航。
- 不使用五颜六色标签。
- 绿色只可用于少量强调。

### 图片

职责：

- 展示内容证据、作品材料、图表或附件。

规则：

- 不做纯装饰图。
- 不使用暗色模糊背景图遮盖文字。
- 图片缺失时必须有良好 fallback。
- 图片说明应清晰但克制。

### 分享图入口

职责：

- 让内容容易转发到微信朋友圈。

规则：

- 入口可以低调，但必须能找到。
- 分享图不应变成页面主视觉。
- 生成图风格必须和站点一致。

## 明确禁止

- 禁止营销型 landing page。
- 禁止大面积渐变和装饰性光斑。
- 禁止全站同质化卡片堆叠。
- 禁止为了美观强制要求每篇文章必须有封面。
- 禁止把短动态做成社交平台信息流。
- 禁止第一版引入登录、评论、点赞、收藏。
- 禁止让数据库成为正文内容来源。
- 禁止让统计功能阻塞核心页面。
- 禁止把每种 type 设计成互相割裂的独立风格。
- 禁止在页面上写大段“本站功能说明”式文案。

## 设计师自由空间

设计师可以自由决定：

- 首屏的具体构图。
- 首页模块顺序。
- 字体搭配。
- 细线、编号、表格、索引等档案元素的使用方式。
- 列表密度。
- 目录树视觉。
- 时间线形式。
- 分享图模板细节。
- 动效节奏。

但最终效果必须服务于：

- 个人档案馆。
- 长期写作。
- 作品展示。
- 快速检索。
- 黑白学术感。
- 少量绿色个人识别。
