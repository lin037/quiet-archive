# Sevth Blog 产品需求文档

## 产品定位

Sevth Blog 是一个个人学术档案馆式博客，用来长期保存写作、工程记录、项目作品、回答、随笔、专栏，以及未来可被 AI 读取和复用的个人知识资产。

它不是社交平台，不是通用 CMS，也不是营销型作品集。第一版应该像一个私人研究档案馆被有选择地公开出来：安静、结构化、个人化、可持续。

核心目标：

- 记录个人思考、工程实践、项目进展、问答、短笔记和长期专栏。
- 对朋友、同行和未来合作者清晰展示“我是一个怎样的人”。
- 使用 Git 管理内容文件，让博客天然具备历史记录和知识库属性。
- 支持生成论文封面感分享图，方便在微信朋友圈传播。
- 系统足够简单，可以部署在个人服务器上，不依赖大型数据库。

用户优先级：

1. 作者自己。
2. 作品集读者和同行。
3. 来自微信朋友圈或外部链接的公开读者。

## 视觉方向

视觉关键词：

```txt
黑白学术档案馆 + 安静工程师 + 少量绿色点睛
```

设计原则：

- 网站应该像档案馆，而不是落地页。
- 个人识别度主要来自字体、版式、节奏和细节，不依赖大面积装饰。
- 黑白灰是主色，绿色只用于链接、状态、标记、统计点、选中态等小面积元素。
- 图片可以出现，但必须像内容证据、作品材料或档案附件，而不是默认作为大面积装饰。
- 没有图片时页面也必须完整、优雅、有设计感。
- 风格要简约、克制、可识别，不做普通博客模板感。
- 长文阅读必须舒适，技术文章要务实、清晰、精确。
- 文学、故事、世界观类专栏可以存在，但视觉上仍然属于同一个档案系统。

图片策略：

- `cover` 是可选字段。
- 有 `cover` 时，图片增强内容，不抢正文。
- 没有 `cover` 时，使用排版、编号、元信息和细线生成封面感。
- 分享图是独立生成的资源，不要求直接复用页面封面。

页面级模块、模块职责和明确禁止项见 `docs/page-design-spec.md`。

## 内容类型

站点支持七种一等内容类型：

| 类型 | 用途 | 默认展示 |
| --- | --- | --- |
| `article` | 正式技术文章、结构化文章、长文思考 | 正式文章版式 |
| `note` | 短随笔、公开动态、朋友圈式片段 | 时间线版式 |
| `answer` | 对别人问题的回答，或自问自答 | 问答版式 |
| `project-log` | 项目推进记录、阶段复盘、开发日志 | 项目时间线版式 |
| `column` | 长期专栏、连载写作、故事或书籍式内容 | 书籍/章节版式 |
| `work` | 作品、项目、工具、系统、Demo | 作品档案版式 |
| `experiment` | 小实验、原型、技术试验 | 实验报告版式 |

短动态从第一版内容模型开始支持，但第一版不要求做复杂的社交流动态页。

## 第一版范围

第一版必须包含：

- 首页：个人档案入口。
- 混合归档页：展示所有公开内容。
- 七种内容类型的类型页。
- 从 `README.md` 生成的目录页、专题页、卷页或集合页。
- Markdown 和 MDX 内容详情页。
- 作品页。
- 专栏页，支持卷、章节或目录式导航。
- 搜索页或搜索浮层，支持快速模糊全文搜索和中文搜索。
- 论文封面感分享图生成。
- 基于索引生成的基础内容统计，例如内容数、类型数、最近更新。
- `assets/` 静态资源管理。
- 内容校验脚本和索引生成脚本。

第一版暂不做：

- 登录系统。
- 评论系统。
- 后台 CMS。
- 完整 AI Agent。
- 推荐算法。
- 重型访问分析。
- 真实公开流量看板。

后续可选：

- SQLite 页面浏览计数。
- 本地 embedding 缓存。
- AI 摘要生成。
- 更强的中文搜索引擎。

## 首页需求

首页首屏要回答四个问题：

- 这个人是谁？
- 他现在关注什么？
- 他做过什么？
- 他正在写什么、维护什么？

建议首页模块：

1. 个人档案头部：
   - 名字或 handle。
   - 极短身份描述。
   - 当前关注方向。
   - 内容总数、最近更新时间等稀疏元信息。
2. 精选作品：
   - 少量精选 `work`。
3. 最近写作：
   - 混合展示 `article`、`answer`、`project-log`、`column`。
4. 正在维护的专栏：
   - 展示长期写作项目。
5. 档案脉搏：
   - 总内容数、各类型数量、最近更新、活跃专栏等生成统计。

## 分享需求

分享主要面向微信朋友圈。

分享图风格：

- 论文封面感。
- 黑白基底。
- 少量绿色点睛。
- 强标题层级。
- 包含内容类型、标题、日期、路径或站点签名。
- 本地生成或内容更新时生成，然后随 Git 提交。

当内容存在生成分享图时，站点应使用该图作为 Open Graph 图片。

## 搜索需求

第一版必须支持快速模糊搜索，并且支持中文内容。

搜索范围：

- 标题。
- 摘要。
- 标签。
- 所属目录标题。
- 正文标题层级。
- 正文纯文本。
- 内容类型。
- URI。

期望行为：

- 输入时响应足够快。
- 不依赖大型后端数据库。
- 搜索索引在构建或内容同步阶段生成。
- 中文分词在脚本阶段完成，不在每次浏览器搜索时临时处理。

## 非目标

第一版不把项目做成完整 CMS。

内容唯一事实来源是 Git 中的文件。运行时数据不能成为渲染核心档案的必要依赖。

视觉上不追求常见博客模板、亮色渐变、社交信息流噪音或过度装饰的作品集风格。
