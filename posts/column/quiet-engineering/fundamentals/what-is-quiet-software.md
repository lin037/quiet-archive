## 一个思想实验

想象两个闹钟应用：

**闹钟 A**：
- 打开时显示一个大大的时间
- 设置闹钟只需要两步：选时间、确认
- 闹钟响了，关掉就好
- 没有社交功能、没有成就系统、没有每日推送

**闹钟 B**：
- 打开时显示你的「睡眠评分」和「起床排名」
- 设置闹钟时推荐你「最佳起床时间」
- 闹钟响了，要求你完成一个小游戏才能关掉
- 每天推送「你比 73% 的用户起得早」
- 有好友排行榜和连续早起徽章

闹钟 A 是安静的软件。闹钟 B 不是。

## 安静软件的定义

**安静的软件**是指：完成用户的核心任务后，不再试图占据用户更多的注意力和时间的软件。

它有几个核心特征：

### 1. 不制造需求

安静的软件不会让你觉得「我应该更多地使用这个应用」。它不会用红点、徽章、连续天数来制造虚假的紧迫感。

```
// 安静的设计
function onTaskComplete() {
  showConfirmation("已完成");
  // 就这样。不推荐下一个任务，不显示统计，不弹出分享。
}

// 不安静的设计
function onTaskComplete() {
  showConfirmation("已完成！");
  showStreak("连续 7 天完成任务！");
  suggestNextTask("要不要再做一个？");
  promptShare("分享给朋友看看？");
  showLeaderboard("你在好友中排名第 3！");
}
```

### 2. 不追求参与度

现代软件行业的核心指标是「用户参与度」——DAU、使用时长、打开频次。安静的软件拒绝这个框架。

一个好的笔记应用，最理想的使用方式是：

- 有想法时打开，快速记录
- 需要回顾时打开，快速找到
- 其余时间，它不存在

如果一个笔记应用让你每天花 2 小时在「整理笔记系统」上，它就不是安静的——即使它的功能很强大。

### 3. 不绑架数据

安静的软件让你随时可以离开。你的数据是你的，格式是通用的，导出是无障碍的。

```
# 安静的数据存储
posts/
├── my-article.md      ← 纯文本，任何编辑器都能打开
├── my-note.md         ← 不需要特定应用才能阅读
└── my-project.md      ← 10 年后依然可读

# 不安静的数据存储
database.sqlite        ← 需要特定应用才能解读
sync-blob-v3.dat       ← 专有格式，离开应用就是废数据
```

### 4. 不追求增长

安静的软件不需要「增长」。它不需要更多用户、更多功能、更多收入来证明自己的价值。

一个为 100 个人服务得很好的工具，不需要变成为 100 万人服务的平台。

## 为什么安静很难

安静的软件在商业上是反直觉的：

- 投资人要看增长曲线
- 产品经理要提高参与度
- 设计师要展示创新
- 工程师要用新技术

整个行业的激励结构都在推动软件变得更「吵」。

但作为个人开发者，我们有一个独特的优势：**我们不需要向任何人证明增长。** 我们可以为自己构建安静的软件，然后把它分享给同样需要安静的人。

## 安静工程学的第一原则

> 软件应该像一把好椅子：你坐下时感到舒适，站起来时不会想到它。

这是安静工程学的第一原则。后续的文章会探讨如何在技术层面实现这个原则——从架构设计到 API 设计，从部署策略到维护哲学。

## 一些安静软件的例子

- **curl**：发送 HTTP 请求，返回结果，结束。没有账号系统，没有使用统计，没有更新提醒。
- **SQLite**：一个文件就是一个数据库。不需要服务器，不需要配置，不需要维护。
- **Markdown**：纯文本格式。任何编辑器都能打开，100 年后依然可读。
- **RSS**：订阅内容，按自己的节奏阅读。没有算法推荐，没有无限滚动。

这些工具的共同点：**它们完成任务后就消失了。** 它们不试图成为你生活的中心。
