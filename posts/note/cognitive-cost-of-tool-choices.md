## 无限选择的焦虑

今天想记一个观察：我花了 45 分钟在选择一个 Markdown 编辑器。

不是因为没有好的选择——恰恰相反，是因为选择太多了。Obsidian、Logseq、Notion、Typora、VS Code + 插件、Vim + 插件……每一个都有独特的优势，每一个都有热情的社区在推荐。

最终我意识到：**选择工具的时间，已经超过了我今天要写的内容所需的时间。**

## 认知预算是有限的

Daniel Kahneman 在《思考，快与慢》中提出了一个重要概念：认知资源是有限的。每一个决策——无论多小——都在消耗你的认知预算。

工具选择是一种特别隐蔽的认知消耗，因为它伪装成了「提高效率」：

- 「如果我找到更好的工具，以后每天都能省 5 分钟」
- 「这个工具的插件生态更好，长期来看更值得投入」
- 「先花时间调研清楚，避免以后迁移的成本」

这些理由听起来都很合理。但它们忽略了一个事实：**你在调研工具的时候，什么实际工作都没有完成。**

## 「够用」的判断标准

我现在用一个简单的框架来判断一个工具是否「够用」：

1. **它能完成核心任务吗？** 如果能，就够了
2. **它会在日常使用中造成明显的摩擦吗？** 如果不会，就够了
3. **切换到另一个工具的收益，能覆盖学习和迁移的成本吗？** 如果不能，就别换

## 一个反直觉的结论

最高效的人往往不是使用最好工具的人，而是**最快做出工具决策并开始工作的人**。

他们可能用着「不完美」的工具，但他们把省下来的认知预算用在了真正重要的事情上：思考、创造、执行。
